# Experiment log

Every experiment has an ID, a hypothesis, what was run, and the outcome. Outcomes are marked **POSITIVE** (the hypothesis was confirmed), **NEGATIVE** (rejected) or **INFO** (a measurement). Unsuccessful experiments stay in this log so that they are not repeated. Result files are in `results/`; analysis reports are named in each entry.

## Rejected ideas (do not repeat without a new reason)

- Route prior from reconstruction labels used for top-K pruning (E03–E06).
- "The network pushes requests back to their origin route" as explanation (E05, section C: the data show the opposite).
- Stronger guidance (larger lambda, smaller K): monotonically worse (E03).
- Learned choice of the destroy neighbourhood by one-step improvement: at most about 0.7% with a perfect selector (E08a).
- Guide from the run's own best solution (self-consensus): strongly harmful (E08b).
- Guide from a teacher that is not better than the search (0.6× or 1× run; the old co-routing head): neutral to harmful (E08b, E08c).
- Pruning with predicted advice: harmful on H-DARP style even when the advice is an oracle (E09b).
- Static relatedness as guide: harmful (E09b).
- Oracle used only as destroy operator: no significant effect (E09b).
- Per-instance choice of the removal share and noise level: no held-out gain (E11).
- Static, instance-level co-routing prediction as a prior (old head, teacher-trained HGNN, homogeneous GNN, no message passing): not better than classical ALNS; harmful with a strong prior (E13, E14).
- Soft consensus of several long runs with a strong prior: harmful on H-DARP style (E14). Only one specific better solution helps.
